# 화면별 동작·검증 Design Review

작성일 2026-08-05 · 상태 **확정(4단계)** · 선행 [kpi-domain-model.md](kpi-domain-model.md), [stack-and-structure.md](stack-and-structure.md), [server-action-contract.md](server-action-contract.md)

설계 순서 중 **④ 화면별 동작·검증** 단계다. 화면 4개의 상호작용, 유효성 메시지, 빈 상태·에러 상태, 접근성을 잠근다. 인증·인가는 ⑤에서 **데모 전제로 만들지 않기로** 확정했다([auth-demo-scope.md](auth-demo-scope.md)).

## 목표

- 시안 4장을 구현 가능한 동작 명세로 바꾼다.
- 시안에 그려지지 않은 상태(0건, 로딩, 404, 오류, 경계 조작)를 채운다.

## 이번 단계에서 닫은 결정

| 항목 | 결정 |
|---|---|
| 목록 기본 정렬 | **기준기간 내림차순 → 부서명 → 팀(빈 값 마지막) → 이름** 가나다순 |
| 달성률 상한 표시 | **표시한다.** 상한이 걸린 항목의 달성률 옆에 안내 |
| 평가영역 입력 | **기존 값 자동완성 + 자유 입력** |
| 인증 | ⑤에서 **데모 전제로 인증 없음** 확정. 접근 제한은 Vercel Deployment Protection([auth-demo-scope.md](auth-demo-scope.md)) |

### 목록 정렬의 근거

시안 목록 10개 행의 순서가 이 정렬과 정확히 일치한다.

| # | 이름 | 부서명 | 팀 | 기준 기간 |
|---|---|---|---|---|
| 1 | 이명희 | 개발본부 | 서비스팀 | 하반기 |
| 2 | 김철수 | 개발본부 | 플랫폼팀 | 하반기 |
| 3 | 홍길동 | 개발본부 | 플랫폼팀 | 하반기 |
| 4 | 정태현 | 경영지원본부 | 인사팀 | 하반기 |
| 5 | 강수연 | 경영지원본부 | `-` | 하반기 |
| 6 | 박지성 | 영업본부 | 영업1팀 | 하반기 |
| 7 | 최민아 | 영업본부 | 영업2팀 | 하반기 |
| 8 | 오정민 | 개발본부 | 서비스팀 | 상반기 |
| 9 | 윤태진 | 개발본부 | 플랫폼팀 | 상반기 |
| 10 | 한명수 | 개발본부 | `-` | 상반기 |

- 하반기 7건이 먼저, 상반기 3건이 나중 → 기준기간 내림차순.
- 부서 개발본부 → 경영지원본부 → 영업본부 → 가나다순.
- 같은 부서 안에서 서비스팀 → 플랫폼팀, 영업1팀 → 영업2팀 → 팀 가나다순.
- 같은 팀 안에서 김철수 → 홍길동 → 이름 가나다순.
- 팀이 `-`인 행(5번 강수연, 10번 한명수)은 각 그룹의 **마지막** → 빈 값 후순위.

**종합 달성률 정렬은 제공하지 않는다.** 저장하지 않는 파생값이라(①) DB 정렬이 불가능하고, 전수 로드 후 메모리 정렬로 하면 건수가 늘 때 페이지네이션이 깨진다. 필요해지면 집계 컬럼 도입을 먼저 결정한다.

## 시안 재정독에서 나온 수정 사항

### 1. `직책`과 `기준연도`는 셀렉트다 — 고정 목록이 존재한다

등록/수정 시안에서 `직책 *`과 `기준연도 *`는 텍스트 입력이 아니라 **셀렉트**다. ①에서 `position`을 자유 문자열로 적은 것은 부정확하다.

시안 10건에서 관찰된 직책: `사원`, `대리`, `과장`, `선임`, `책임`, `팀장`, `실장`, `본부장` (8개).

- 목록을 `lib/kpi/constants.ts` 상수 배열 한 곳에 두고 셀렉트 옵션과 검증이 공유한다.
- DB 타입은 문자열로 두고 `enum`을 쓰지 않는다. 목록이 늘어날 때 마이그레이션이 필요해지는 것을 피한다.
- **확인 필요**: 관찰된 8개가 전부인지, 표시 순서를 직급 순으로 할지 가나다순으로 할지. 시안은 근거를 주지 않는다. 우선 관찰 순서를 직급 흐름(`사원 → 대리 → 과장 → 선임 → 책임 → 팀장 → 실장 → 본부장`)으로 두고 확인받는다.
- `기준연도`도 셀렉트다. 시안 값은 `2026` 하나다. 현재 연도 기준 범위로 만들어야 하며 **폭은 확인 필요**.

### 2. 저장 버튼을 비활성으로 두지 않는다 — ③ 수정

③에서 "가중치 합이 100%가 아니면 저장 버튼을 비활성한다"고 적었는데, 이를 **버튼은 활성으로 두고 클릭 시 검증**으로 바꾼다.

- 접근성: `disabled` 버튼은 키보드 포커스를 받지 못하고 스크린리더가 "왜 못 누르는지"를 읽어주지 못한다. 사용자가 막힌 이유를 알 수 없다.
- 시안 근거: 수정 시안은 합계가 80%인데도 `저장` 버튼이 활성 상태로 보인다.
- 데이터 정합성은 그대로다. zod와 DB 제약이 최종 방어선이므로(③) 잘못된 값은 저장되지 않는다.
- 클릭 시 동작: 검증 실패 → 하단 바 메시지를 강조하고 **첫 오류 필드로 포커스 이동**.

## 공통 레이아웃

- 상단 바에 `KPI 대시보드`. 목록(`/kpi`)으로 가는 링크로 만든다.
- `/`는 `/kpi`로 리다이렉트한다(②).
- 카드는 흰 배경 + 얇은 테두리 + 라운드, 배경은 아주 연한 회색. 시안 톤을 따른다.
- 표시 반올림은 `lib/format.ts` 한 곳에서만 한다(①).

## 목록 — `/kpi`

### 구성

- 제목 `KPI 목록`(좌), 우상단 `KPI 등록` 버튼(검정 채움).
- 필터 카드: `부서명`·`팀`·`이름` 텍스트 입력 3개, `직책`·`기준 기간` 셀렉트 2개(기본값 `전체`). 우하단에 `초기화`·`검색`.
- 건수 `총 N건`을 표 위 좌측에 둔다.
- 표 컬럼: 이름(굵게) · 부서명 · 팀 · 직책 · 기준 기간 · 종합 달성률 · 상세보기.
- 종합 달성률 셀: `60.0%` + 배지(색 점 + 라벨). 배지는 `양호`/`우려`/`미달`(①).
- 팀이 빈 값이면 `-`.
- 마지막 컬럼에 `상세보기` 아웃라인 버튼 → `/kpi/{id}`.
- 페이지네이션: `이전` · 페이지 번호 · `다음`. 현재 페이지는 검정 채움. 1페이지에서 `이전`, 마지막에서 `다음`은 비활성.

### 동작

- 필터 상태는 URL searchParams에 둔다(③). 새로고침·공유·뒤로가기가 그대로 동작한다.
- `검색` → 필터 값을 URL에 반영하고 **`page`를 1로 되돌린다.** 3페이지에서 조건을 좁히면 결과가 1페이지뿐일 수 있어, 리셋하지 않으면 빈 화면이 나온다.
- `초기화` → 필터를 모두 비우고 `page=1`로 재조회. 조건 없는 전체 조회와 같다(③).
- 셀렉트 옵션은 **DB에 실제로 존재하는 값**으로 만든다.
  - `기준 기간`: 저장된 `(baseYear, baseHalf)` 조합을 distinct로 뽑아 내림차순. 없는 기간을 고르면 항상 0건이라 의미가 없다.
  - `직책`: 위 상수 목록을 쓴다. 셀렉트로 입력받은 값이므로 표기 분화가 없다.

## 등록 — `/kpi/new`

### 구성

- 제목 `KPI 등록`.
- 섹션 `사원 정보`: 1행에 `아이디*`·`이름*`·`부서명*`·`팀`, 2행에 `직책*`·`기준연도*`·`기준 반기*`. 시안 라벨 `기준분기`는 `기준 반기`로 고친다(①).
- 섹션 `KPI 항목`. 섹션 설명은 시안 문구를 유지한다 — 동일 평가영역 항목을 인접 배치하면 상세에서 묶여 표시된다는 안내다. 상세의 병합 규칙과 실제로 일치한다.
- 항목 카드마다 번호와 우측 `↑`·`↓`·`삭제`.
  - 1행: `평가영역*`·`항목*`·`측정지표`·`목표치`
  - 2행: `목표개수*`·`달성개수*`(기본 `0`)·`가중치(%)*`
- `+ 항목 추가` 아웃라인 버튼.
- 하단 고정 바: 좌측에 현재 합계와 안내, 우측에 `취소`·`저장`.

### 동작

- `+ 항목 추가` → 빈 항목을 끝에 붙이고 번호를 다시 매긴다. 새 항목의 첫 필드로 포커스를 옮긴다.
- `삭제` → 항목이 1개만 남으면 비활성한다(③: 최소 1개).
- `↑`는 첫 항목에서, `↓`는 마지막 항목에서 비활성.
- 하단 바 합계는 **입력할 때마다 실시간 계산**한다. 계산은 `calc`/`schema`의 정수 환산 방식을 그대로 쓴다(②·③). 화면에서 부동소수로 더하지 않는다.
- 하단 바 문구는 ①에서 정한 교체 문구를 쓴다: 합이 100%가 아니면 `저장하려면 가중치 합이 100%여야 합니다 (현재 N%)`. 시안의 `미달분은 달성률에 반영되지 않습니다`는 쓰지 않는다.
- `저장` → 검증 통과 시 Server Action 호출, 성공하면 상세로 이동.
- `DUPLICATE_PERIOD` → 폼 상단 배너로 안내하고 **입력값을 유지한다**(③).
- `취소` → 변경사항이 있으면 확인을 받고 목록으로. 변경이 없으면 바로 이동.
- `평가영역`은 기존 값 자동완성이 붙은 입력이다. 저장 시 `trim()`(③).

## 상세 — `/kpi/[id]`

### 구성

- 좌상단 `← 목록으로`.
- 제목 `KPI 상세`, 우상단 `수정`·`삭제`.
- 카드 `사원 정보`: 이름·부서명·팀·직책, 다음 행에 기준 기간(`2026년 하반기`). 읽기 전용.
- 좌측 카드 `종합 달성률`: 큰 숫자 `90.0%` + 배지.
- 우측 카드 `평가영역별 비중`: 도넛 + 범례 `개발 (70%)` / `품질 (30%)`.
- 카드 `KPI 항목` 표: 평가영역 · 항목 · 측정지표 · 목표치 · 목표개수 · 달성개수 · 가중치 · 달성률 · 가중점수.

### 평가영역 셀 병합

- **인접한 동일 평가영역만** 하나의 셀로 병합한다(`rowspan`). 시안에서 `개발` 2행이 병합되어 있고, 등록 화면의 안내문과도 일치한다.
- 인접하지 않은 동일 값은 병합하지 않는다. 정렬로 재배치하지 않는다 — 항목 순서는 사용자가 정한 `sortOrder`가 유일한 기준이다(③).
- 도넛의 영역 비중은 병합과 무관하게 **같은 이름을 모두 합산**한다(①). 병합은 표시 규칙, 합산은 계산 규칙이다. 인접하지 않은 같은 이름이 있으면 표는 두 덩어리로 보이지만 도넛은 한 조각이다.

### 상한 표시

- 달성률이 100% 상한에 걸린 항목(예: 12/10)은 달성률 셀에 `(상한)`을 붙이고 `목표 초과, 100%로 상한 적용`을 알린다.
- 표의 `목표개수`·`달성개수`는 원본 그대로 `10`·`12`를 보여준다(③).
- **목표개수가 0인 항목에는 아무 표기도 붙이지 않는다.** 달성률만 `100.0%`로 나온다. `(상한)`도 붙지 않는다 — 초과 달성이 아니기 때문이다. (2026-08-06 결정: `(목표 미설정)` 표기를 넣었다가 제거했다. 목표개수 열에 `0`이 그대로 보이므로 별도 안내가 없어도 원인을 알 수 있다.)

### 동작

- `삭제` → 확인 대화상자 → 소프트 삭제 → 목록으로 이동하고 결과를 알린다.
- 대상이 없거나 이미 삭제됐으면 404(③의 `NOT_FOUND`).
- `수정` → `/kpi/{id}/edit`.

## 수정 — `/kpi/[id]/edit`

- 등록과 같은 폼에 기존 값이 채워지고 제목만 `KPI 수정`이다.
- 항목은 저장 시 전체 교체된다(③). 화면에서는 순서 이동·추가·삭제가 자유롭다.
- 저장 성공 → 상세로 이동.
- 폼을 열어 둔 사이 대상이 삭제됐으면 저장 시 `NOT_FOUND`가 온다. 폼을 유지하지 말고 목록으로 보낸다(③).

## 빈 상태 · 로딩 · 오류

| 상황 | 화면 |
|---|---|
| 필터 결과 0건 | `조건에 맞는 KPI가 없습니다` + `필터 초기화` 링크 |
| 전체 데이터 0건 | `등록된 KPI가 없습니다` + `KPI 등록` 유도 |
| 목록·상세 로딩 | `loading.tsx`로 표 골격 스켈레톤 |
| 상세 404 | `not-found.tsx` — `요청한 KPI를 찾을 수 없습니다` + 목록 링크 |
| 예기치 못한 오류 | `error.tsx` — 재시도 버튼. 검증 실패는 여기로 오지 않는다(③) |

두 빈 상태를 구분하는 이유: 필터 때문에 0건인 것과 데이터가 아예 없는 것은 사용자가 취할 행동이 다르다.

## 접근성

- 모든 입력에 `<label>`을 연결한다. 시안이 라벨을 필드 위에 두고 있어 구조가 그대로 맞는다.
- 필수 표시 `*`는 시각 정보이므로 `aria-required`를 함께 준다.
- **배지는 색만으로 구분하지 않는다.** 시안이 이미 색 점과 텍스트 라벨을 함께 쓰고 있어 색각 이상 사용자도 구분할 수 있다. 이 구조를 유지한다.
- 도넛도 색만으로 구분되므로 **범례 텍스트가 필수**다(시안에 있다). 같은 수치가 아래 표에도 있어 대체 경로가 존재한다.
- `↑`·`↓` 아이콘 버튼에 `위로 이동`·`아래로 이동` 레이블을 준다. 아이콘만 두지 않는다.
- 하단 고정 바의 합계·경고는 `aria-live="polite"`로 알린다. 값이 바뀔 때 스크린리더가 읽는다.
- 저장 버튼은 비활성으로 두지 않는다(위 수정 사항 2). 실패 시 첫 오류 필드로 포커스를 옮긴다.
- `삭제`는 빨강 색만으로 위험을 표현하지 않고 확인 대화상자로 이중 확인한다.
- 하단 고정 바가 마지막 항목을 덮지 않도록 폼 하단에 여백을 둔다.

## 검증 기준

- 단위 테스트 (Vitest)
  - 정렬 비교 함수: 위 10행 표의 입력을 섞어 넣으면 표와 같은 순서로 정렬된다. 팀이 `null`인 행이 그룹 마지막에 온다.
  - 평가영역 병합 계산: `[개발, 개발, 품질]` → `rowspan` 2와 1. `[개발, 품질, 개발]` → 병합 없음(3덩어리), 도넛은 `개발` 하나로 합산.
  - 상한 판정: 12/10 → 상한 표시 대상, 10/10 → 대상 아님, 목표개수 0 → 대상 아님(초과 달성이 아니다).
- E2E (Playwright)
  - 3페이지에서 필터를 좁혀 `검색` → 1페이지로 이동하고 결과가 보인다.
  - `초기화` → 필터가 비고 전체 목록이 나온다.
  - 항목 1개만 남았을 때 `삭제`가 비활성이다.
  - 첫 항목의 `↑`, 마지막 항목의 `↓`가 비활성이다.
  - 가중치 합 80% 상태에서 `저장`을 누르면 저장되지 않고 하단 바 메시지가 강조되며 포커스가 첫 오류로 간다.
  - `33.33`·`33.33`·`33.34` 입력 시 합계가 `100%`로 표시되고 저장된다(부동소수 오탐 없음).
  - 상세에서 `삭제` → 확인 → 목록에서 사라지고 상세 URL 직접 접근 시 404.
  - 필터로 0건을 만들면 `조건에 맞는 KPI가 없습니다`가, 데이터가 없으면 `등록된 KPI가 없습니다`가 나온다.
- 접근성 검증
  - 키보드만으로 등록 폼을 처음부터 저장까지 완료할 수 있다.
  - 배지와 도넛 정보가 색 없이도 텍스트로 전달된다.

## Out of Scope

- 인증·인가 — ⑤에서 만들지 않기로 확정([auth-demo-scope.md](auth-demo-scope.md))
- 목록 정렬 변경 UI, 컬럼 선택, 엑셀 내려받기
- 삭제 복원 화면(③)
- 평가영역 코드 마스터 관리 화면(①의 미해결 7 — 자동완성으로 완화만 했다)
- 반응형 모바일 레이아웃. 시안이 데스크톱 폭 기준이다. 필요 여부는 확인 필요
